# 路线图：补齐产品差距（跨平台 + memory + 工作流 + 上下文 + 工具）

> 日期：2026-07-13
> 背景：与 Claudette 横向对比后，确认 5 大差距（memory / 工作流 / 上下文 / 工具丰富 / **跨平台**）。
> 硬约束（全程遵守）：
> - **零原生编译依赖、U 盘直拷即跑**：存储已用 sql.js；新增依赖必须是纯 JS（npm 装后连同 node_modules 拷贝即可）。
> - **完全离线、内网断网**：模型走本地 Ollama；不调任何云 API 做 embedding / 检索。
> - **三端可跑**：Windows / macOS / Linux。

## 执行顺序（强依赖）

```
P0  跨平台兼容  ──►  所有其他功能的前提（P1-P4 在 Windows 上跑不起来都是零）
  │
  ▼
P1  三级 memory + recall  ──►  差距最大、跨会话复用
  │
  ▼
P2  工作流（规划+验证闭环）  ──►  轻量 Forge，不硬切多角色
  │
  ▼
P3  上下文管理  ──►  压缩 + 真实 token 预算
  │
  ▼
P4  工具丰富  ──►  只补"离线编程 Agent"定位相关的工具
```

**为什么跨平台必须第一**：当前 `bash.js` 无 `shell:true` 且假设 Unix 命令、`explain_symbol`/`find_references` 直接 spawn 系统 `grep`、`start.sh` 是 bash 脚本、`fs.watch recursive` 在 Linux 无效——这四点会让项目在 Windows 上完全起不来，在 Linux 上热重载失效。P1-P4 任何功能在修好跨平台前都是空中楼阁。

## 跨平台 bash 决策（已与用户确认）

> **bash 工具按 platform 选择执行方式**：
> - Windows → `cmd.exe /d /c "<命令>"` 或 PowerShell；禁止依赖非内置 Unix 命令（ls/cat/grep/tree）。
> - macOS / Linux → `/bin/sh -c "<命令>"`（现状）。
> 命令黑名单/白名单按平台分别处理（白名单只读命令在 Windows 上映射到等价内置命令或拒绝）。

## 不做的事（防范围蔓延）

- **不做** Claudette 的 Telegram / Gmail / 日历 / 语音——与"内网断网编程 Agent"定位不符，且违反离线约束。
- **不做** 完整 Forge 多角色硬切流水线（Planner/Coder/Verifier 分进程）——本地弱模型失败率高、徒增 token；只做"规划+验证闭环"。
- **不引入** 任何需 node-gyp 编译的包（如原生 sqlite、sharp、bcrypt）；embedding 走 Ollama 本地模型而非 npm 包。
