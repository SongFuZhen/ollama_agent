# 本地 Agent 客户端 — 项目构想

> 2026-07-09 整理

## 背景

### 现状

- 本地有 Ollama + Qwen-2.5:7B/14B，显卡 5060 8GB
- 目前只用 Chatbox 聊天，体验很差：模型凭空瞎编、不知所云
- 内网环境完全断网，数据出不去
- 云端大模型（Claude、GPT）在内网无法使用

### 核心洞察

Chatbox 让 7B 模型自由发挥 → 模型弱 + 没有约束 = 瞎编。

Agent 模式可以改变用法：**不让模型凭空回答，先调工具拿真数据，再对着数据回答**。模型还是那个模型，但输入和约束完全不同。

## 项目定位

做一个**本地 Web 应用**，在家写好、U盘搬到内网、一行命令启动。

- 不是 Chatbox 的替代品
- 不是 Claude Code 的平替
- 是内网环境里唯一能用的、有约束的、不瞎编的 AI 助手

## 技术架构

```
┌──────────────────────────────────────┐
│  浏览器前端                           │
│  对话界面 + 工具调用过程可视化          │
│  纯 HTML/CSS/JS                      │
└──────────────┬───────────────────────┘
               │ HTTP + SSE（流式）
┌──────────────▼───────────────────────┐
│  Node.js + Express 后端               │
│  ┌─────────────────────────────────┐ │
│  │ Agent Loop                      │ │
│  │  while (未完成) {                │ │
│  │    LLM思考 → 判断是否调工具       │ │
│  │    → 执行工具 → 结果喂回          │ │
│  │    → 重新思考 → ...              │ │
│  │  }                              │ │
│  ├─────────────────────────────────┤ │
│  │ Tool Registry（工具注册中心）     │ │
│  │  - read_file(path)              │ │
│  │  - write_file(path, content)    │ │
│  │  - list_dir(path)               │ │
│  │  - search_files(pattern)        │ │
│  │  - （可扩展）                    │ │
│  ├─────────────────────────────────┤ │
│  │ Memory                          │ │
│  │  - 对话历史（工作记忆）           │ │
│  │  - 会话摘要（短期记忆）           │ │
│  └─────────────────────────────────┘ │
└──────────────┬───────────────────────┘
               │ HTTP POST localhost:11434
┌──────────────▼───────────────────────┐
│  Ollama                              │
│  qwen2.5:7b / 14b / nomic-embed-text │
└──────────────────────────────────────┘
```

### 为什么选 Node.js 而不是 Tauri

- 项目本质是 Web 服务，Tauri 多一层 Rust/桌面壳完全没必要
- `fs` 模块原生支持文件读写，比 Tauri invoke 更简单
- 前后端都是 JS，一套语言打通
- 内网浏览器打开即用，不需要安装客户端

## 核心功能

### V1（最小可用）

1. **对话界面** — 输入框 + 消息列表，基础聊天
2. **Agent 循环** — `while True` 的核心循环跑通
3. **至少一个 Tool** — `read_file`，读取本地文件并把内容注入 prompt
4. **Ollama 对接** — 调本地模型
5. **思考过程可视化** — 前端能看到 LLM 在想什么、调了什么工具

### V2（增强）

1. 更多 Tools — 写文件、搜文件、列目录
2. 流式输出 — SSE 实时显示模型思考过程
3. 多会话管理
4. 短期记忆 — 自动总结对话

### 远期方向

1. Embedding + RAG — 内部文档知识库
2. 多模型切换
3. 内网部署到局域网，多人使用

## 核心区别：Agent 模式 vs Chatbox

| | Chatbox | 本地 Agent |
|---|---|---|
| 模型拿到什么 | 只有用户的问题 | 用户问题 + 工具返回的真实数据 |
| 回答来源 | 凭空想象 | 对着文件/数据回答 |
| 多步任务 | 不支持 | 拆分→逐步执行 |
| 过程可见 | 只看结果 | 看到思考链+工具调用 |

## 使用场景（内网）

- **代码分析** — 先读文件，再分析，不会瞎编 API
- **文档总结** — 把内部技术文档读进去，基于原文回答
- **辅助写报告** — 给大纲和要点，展开成文（基于已有模板）
- **日志排查** — 读日志文件，找异常点

## 部署方式

```
家里电脑（有网）                    内网电脑（断网）
┌─────────────────┐              ┌─────────────────┐
│ git clone        │              │                 │
│ npm install      │   ──U盘──▶   │ 粘贴到内网电脑    │
│ 开发+调试         │              │                 │
│ 验证流程正确      │              │ npm install     │
│                  │              │ node server.js  │
│                  │              │ 浏览器打开       │
└─────────────────┘              └─────────────────┘
```

Ollama 需要内网电脑提前装好，模型也提前拉好。后续考虑把 Ollama 安装包 + 模型文件一并放 U 盘。
