# Ason Agent vs Claude Code vs OpenCode —— 针对 Ollama 7B 小模型的对比

> 核心命题：当模型从 Claude Sonnet（200K 上下文、强推理）降级到 Ollama 7B（16K 上下文、弱推理、易幻觉）时，
> Agent 框架的设计哲学应该如何改变？
>
> - **Claude Code / OpenCode 范式**：模型是强引擎，框架做"传输层"——暴露工具、接回响应，模型自己负责做对。
> - **Ason Agent 范式**：模型是弱引擎，框架做"babysitter"——不信任模型输出、判断、收敛、记忆、规划，靠工程兜底。

---

## 一、总体定位对比

| 维度 | Claude Code | OpenCode | Ason Agent（本项目） |
|------|-------------|----------|----------------------|
| **目标模型** | Claude 3.5/4 Sonnet+（闭源大模型） | 主流商业 + 开源大模型 | **明确为 Ollama 7B/8B 设计** |
| **核心假设** | 模型可靠，给足工具即可 | 模型较可靠，适配多家 | **模型不可靠，靠工程兜底** |
| **设计哲学** | 强模型 + 自由度 | 多 provider 适配 | **弱模型 + 强约束 + 真数据 = 不瞎编** |
| **运行形态** | CLI | CLI/TUI | **本地 Web 应用**（HTTP+SSE+SPA） |
| **部署场景** | 在线、联网 | 在线、联网 | **内网断网、U 盘直拷即跑** |
| **依赖** | 重（Node + npm 生态） | 中等 | **零依赖**（仅 1 个 sql.js WASM） |
| **数据存储** | 云端 + 本地 | 本地文件 | **SQLite (WASM)**，跨平台零原生编译 |

## 二、Tool Calling 机制对比

| 维度 | Claude Code | OpenCode | Ason Agent |
|------|-------------|----------|------------|
| **调用方式** | 原生 API + 结构化 schema | 原生 API + 多 provider 适配 | **默认 prompt-based 文本 JSON** |
| **原生 tools API** | 全程使用 | 全程使用 | **仅白名单模型启用，当前白名单为空数组**（config.js:36-38） |
| **JSON 容错** | 不需要 | 基本不需要 | **多层容错**：剥注释、修尾逗号、双格式兼容（`{action,params}` / `{name,arguments}`）、`JSON_RETRY=2` |
| **解析回退** | 不需要 | 基本不需要 | 代码块优先 → think 块回退 → raw 文本再解析（agent.js:104-128） |
| **降级机制** | 无 | 无 | 原生路线 `tool_calls` 为空时自动降级到文本解析（agent.js:540-559） |

**关键差异**：Ason Agent 认为"大多数社区 tool-calling 模型只是文本输出 JSON"，因此默认走 prompt-based 路线，并投入大量工程做容错解析——这是 7B 小模型能稳定调工具的基础。

## 三、上下文管理对比

| 维度 | Claude Code | OpenCode | Ason Agent |
|------|-------------|----------|------------|
| **上下文窗口** | 200K，无需精打细算 | 较大，按 provider 而定 | **16K（NUM_CTX=16384）**，激进管理 |
| **Token 估算** | API 精确返回 | API 精确返回 | **`text.length / 2.5`**（中英文混合保守估算），优先用真实 `prompt_eval_count` |
| **截断策略** | 较少截断 | 较少截断 | **System 消息永不清除**（工具列表不能丢）+ 保留最近 K 条 |
| **压缩机制** | 自动摘要 | 自动摘要 | **触发条件**：`lastPromptTokens > NUM_CTX * 0.7`（即 11468 tokens）；**策略**：system + 最近 6 条 + 中间段摘要化为一条 system 消息（compact.js:27-59） |
| **记忆系统** | 单层 | 单层 | **三级**：L1 最近对话（5 条）+ L2 语义召回（embedding 余弦相似度 Top-K）+ L3 关键词降级（SQLite LIKE） |
| **Embedding** | 闭源 API | 闭源 API | **本地 `nomic-embed-text`**（768 维） |

**关键差异**：7B 小模型上下文短、易跑偏，Ason Agent 用"System 永不丢 + 三级记忆 + 主动压缩"三重机制压榨有限窗口。

## 四、错误恢复与循环控制对比

| 维度 | Claude Code | OpenCode | Ason Agent |
|------|-------------|----------|------------|
| **错误恢复** | 依赖模型自我纠正 | 依赖模型自我纠正 | **验证器 + 自愈闭环**：每 2 步跑 run_tests/run_lint，失败注入真实报错，最多重试 3 次（MAX_HEAL_STEPS=3） |
| **成败判定** | 信任模型自述 | 信任模型自述 | **绝不采信模型自述**，输出含"退出码"即失败（agent.js:246） |
| **重试退避** | 无 | 无 | **指数退避**（backoffDelay），避免弱模型连续硬撞同一报错打满 Ollama |
| **最大步数** | 信任模型收敛 | 信任模型收敛 | **MAX_STEPS=6**，防空转 |
| **墙钟超时** | 较长 | 较长 | **AGENT_TIMEOUT_MS=90s**，即使反复调工具不收敛也强制收尾 |
| **单步超时** | - | - | **STEP_TIMEOUT_MS=90s**，超时 `req.destroy()` 防进程假死 |
| **重复调用检测** | 基本无 | 基本无 | **callKey 含路径参数**：`tree`/`list_dir` 不同路径的连续下钻也计入重复；连续 2 次警告，连续 3 次强制收尾（agent.js:596-618） |
| **重复写操作熔断** | 无 | 无 | 连续 3 次相同调用直接强制收尾（agent.js:610-614） |

**关键差异**：这是 Ason Agent **最核心的差异化设计**——把"判断对不对"交给确定性测试，模型只负责改，失败就把报错原样喂回重来。Claude Code/OpenCode 都依赖模型自己判断，这对 7B 是灾难。

## 五、针对小模型弱点的专项容错对比

| 弱模型常见问题 | Claude Code | OpenCode | Ason Agent 的补丁 |
|----------------|-------------|----------|-------------------|
| **路径错误**（绝对路径当相对路径传） | 直接用模型输出 | 直接用模型输出 | **safeResolve 容错归一化**：若绝对路径越界但包含沙箱根为前缀，剥掉前缀当相对路径处理（utils.js:14-65） |
| **JSON 格式错误**（注释、尾逗号） | 不容忍 | 不容忍 | **stripJSONComments + 尾逗号修复**，先抽离字符串字面量避免误伤 `https://`（agent.js:86-100） |
| **逐层下钻死循环** | 信任模型 | 信任模型 | **callKey 含路径参数**，不同路径的连续下钻也计入重复 |
| **长链跑偏** | 信任模型 | 信任模型 | **delegate 子代理委派**：每个子任务全新短上下文 runAgent，不继承主循环冗长历史（delegate.js:1-9） |
| **推理与答案混淆** | 信任模型 | 信任模型 | **think 块分离处理**，部分模型省略 `</think>` 也能处理（agent.js:75-82） |
| **模型完全不可靠时** | 无逃生通道 | 无逃生通道 | **`!`/`@` 直接调用通道**：绕过模型直接执行工具，结果注入上下文（workflow.js:28-53） |

|------|-------------|----------|------------|------|

## 七、安全约束对比

| 维度 | Claude Code | OpenCode | Ason Agent |
|------|-------------|----------|------------|
| **沙箱** | 工作目录 | 工作目录 | **单目录沙箱 + 路径越界检测**（utils.js） |
| **写操作** | 信任模型 | 信任模型 | **二次确认**（server.js `/api/confirm`） |
| **命令执行** | 较宽松 | 较宽松 | **黑/白名单双层**（bash.js） |
| **工具暴露** | 全部 | 全部 | **工具白名单** |
| **防护层数** | 1-2 层 | 1-2 层 | **4 层**：沙箱 + 路径检测 + 写确认 + 命令黑白名单 |

**关键差异**：弱模型更易执行危险操作，Ason Agent 用四层防护把爆炸半径压到最小。

## 八、范式总结

| 范式 | Claude Code / OpenCode | Ason Agent |
|------|------------------------|------------|
| **模型角色** | 强引擎 | 弱引擎 |
| **框架角色** | 传输层 | babysitter（保姆） |
| **信任模型输出？** | 是 | **否**——JSON 多层容错、路径归一化、重复检测、写操作二次确认 |
| **信任模型判断？** | 是 | **否**——验证器跑真实测试判定成败，绝不采信模型自述 |
| **信任模型收敛？** | 是 | **否**——MAX_STEPS、墙钟超时、指数退避、强制收尾 |
| **信任模型记忆？** | 是 | **否**——System 永不丢 + 三级记忆 + 摘要压缩 |
| **信任模型规划？** | 是 | **否**——Plan Mode + delegate 子代理把长链拆成短上下文 |

**一句话**：
- Claude Code / OpenCode 是"**给强模型一双好用的手**"。
- Ason Agent 是"**给弱模型一个不会让它摔倒的护栏**"。

---

## 九、Ason Agent 独有的 7B 优化亮点清单

1. **验证器 + 自愈闭环**（config.js:25-30, agent.js:279-312）——把"判断对不对"交给确定性测试，模型只负责改
2. **路径容错归一化**（utils.js:14-65）——7B 高频错误的专项补丁
3. **重复调用检测含路径参数**（agent.js:596-618）——防逐层下钻死循环
4. **delegate 子代理**（delegate.js:1-9）——用短上下文换可靠性
5. **`!`/`@` 直接调用**（workflow.js:28-53）——弱模型不可靠时的人工逃生通道
6. **JSON 多层容错**（agent.js:86-128）——剥注释、修尾逗号、双格式兼容
7. **System 消息永不清除**（agent.js:36-38）——工具列表不能丢
8. **三级记忆系统**（recall.js）——最近/语义/关键词降级
9. **指数退避自愈**（agent.js:192-195）——防弱模型连续硬撞同一报错
10. **四层安全防护**——沙箱 + 路径检测 + 写确认 + 命令黑白名单
